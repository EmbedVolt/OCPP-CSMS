# OCPP Test CSMS – Web Lab Edition

Compact CSMS for testing **1–10 chargers** through a browser. Supports OCPP **1.6**, **2.0.1**, and **2.1** over JSON/WebSocket.

## Main capabilities

- Real charger WebSocket endpoint: `/ocpp/{stationIdentity}`
- Subprotocols: `ocpp1.6`, `ocpp2.0.1`, `ocpp2.1`
- Browser dashboard
- Charger inventory and connector/EVSE state
- Complete OCPP message log
- Transaction tracking
- Generic schema-driven OCPP console
- Request and response schema validation
- Configurable CSMS response overrides
- **Configuration page**
  - OCPP 1.6: `GetConfiguration` / `ChangeConfiguration`
  - OCPP 2.0.1 / 2.1: `GetVariables` / `SetVariables`
- **Test Center**
  - One test case for every bundled protocol action
  - PASS / FAIL / SKIPPED / timeout reporting
  - Request/response inspection
  - Editable payload per test
  - Safe-query selection
  - Explicit opt-in for state-changing tests
  - Test history persisted in SQLite
- **Virtual Charger from the website**
  - No second terminal required
  - OCPP 1.6 / 2.0.1 / 2.1
  - BootNotification + StatusNotification automatically
  - Can test both Station → CSMS and CSMS → Station messages
- Full bundled-schema self-test from the web UI


## First test – no physical charger

1. Open **Dashboard**.
2. Enter `VIRTUAL-001`.
3. Select OCPP `1.6`, `2.0.1`, or `2.1`.
4. Click **Start virtual charger**.
5. Open **Configuration** to read/change configuration.
6. Open **Test Center**.
7. Click **Select safe queries** or **Select all**.
8. Enable **state-changing tests** only when intended.
9. Click **Run selected tests**.

## Connect a physical charger

Use your PC IPv4 address:

```text
ws://YOUR_PC_IP:9000/ocpp/CHARGER_ID
```

Example:

```text
ws://192.168.1.50:9000/ocpp/EVC5-001
```

The charger must negotiate the appropriate WebSocket subprotocol.

## Configuration page

### OCPP 1.6

Read all configuration:

- leave Keys empty
- click **Read configuration**

Read selected keys:

```text
HeartbeatInterval, MeterValueSampleInterval
```

Change a value:

- select/copy a key
- enter the new value
- click **Change configuration**

### OCPP 2.0.1 / 2.1

The page uses the Device Model:

- Component
- optional Component Instance
- Variable
- optional Variable Instance
- Attribute Type
- Attribute Value

Example:

```text
Component: OCPPCommCtrlr
Variable: HeartbeatInterval
Attribute: Actual
```

The UI sends `GetVariables` or `SetVariables`.

## Test Center behavior

Each bundled request action becomes a test case.

For a **real charger**:

- CSMS → Station actions are actively sent.
- Station → CSMS actions cannot always be forced by the CSMS. Those tests are marked SKIPPED unless the message can be generated by the charger itself.

For the **built-in Virtual Charger**:

- both directions can be generated automatically.
- this is the easiest way to test the complete protocol catalog from the website.

State-changing tests are disabled by default. Examples include:

- Reset
- UnlockConnector
- Request/Remote Start Transaction
- Request/Remote Stop Transaction
- ChangeConfiguration / SetVariables
- Firmware actions
- certificate/network actions
- charging-profile changes

## Generic OCPP Console

Use **OCPP Console** for manual protocol work:

1. Select charger.
2. Select action.
3. Load generated payload.
4. Edit JSON.
5. Send.
6. Inspect CALLRESULT or CALLERROR.

Disable schema validation only for deliberate negative tests.

## Response Rules

For Station → CSMS messages, override the CSMS automatic response without editing Python.

Examples:

- Accepted
- Rejected
- Pending
- invalid authorization response
- custom DataTransfer responses

## Scope

This is a charger development/integration test CSMS. It does not replace the official OCA certification/conformance system and does not include production PKI, payment infrastructure, OCPI, HA, fleet scaling, or multi-tenancy.

## EVC-net-style charge-point portal

Each charger has a complete detail page at:

```text
/stations/<STATION_ID>
```

It now combines the charger workflows in one screen:

- **Dashboard**: connection, delivered-energy estimate, transaction count, last message, current/power/energy chart, occupancy/status history, connector/EVSE state and recent transactions.
- **Test card access**: configure the automatic `Authorize` response (`Accepted`, `Blocked`, `Expired`, `Invalid`, `ConcurrentTx`) and simulate Authorize with the built-in virtual charger.
- **Real-Time**: soft/hard reset, block/unblock, unlock, start/stop transaction, status trigger, clear cache, diagnostics/log, local list, firmware, charging profiles, DataTransfer, TriggerMessage, clear communication history and lab disconnect/clear maintenance.
- **Configuration**: OCPP 1.6 `GetConfiguration`/`ChangeConfiguration`; OCPP 2.x `GetVariables`/`SetVariables`, `GetBaseReport`, `GetReport`.
- **Communication**: full raw CALL/CALLRESULT/CALLERROR history with direction/type/action filters.
- **Transactions**: active and historical transactions with EVSE/connector, ID token and meter information.
- **Tests**: safe suite, full suite, individual action tests, schema validation and PASS/FAIL/SKIPPED results.
- **Diagnostics / Firmware / Security**: GetDiagnostics/GetLog, firmware update, installed/install/delete/sign certificate operations and event history.
- **Station Data**: local friendly name, reference, physical ID, security profile label, allowed IP/CIDR, location, coordinates, remote-access metadata, debug marker and notes. No credentials are rendered or stored in this form.

Complex OCPP commands open an editable JSON payload before transmission. The UI disables actions that are not available in the connected protocol version.

## Charge-point tabs

The charge-point detail page now uses visible top tabs: Dashboard, Real-Time Controls, Configuration, Communication Log, Transactions, Test Center, Diagnostics / Firmware, and Station Data. The Real-Time Controls tab mirrors the EVC-net lab actions. `Get parameters` opens the Configuration tab and executes GetConfiguration for OCPP 1.6 or the GetVariables workflow for OCPP 2.x.
